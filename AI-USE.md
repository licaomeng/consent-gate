- **Tools:** OpenAI Codex for brief analysis, design challenge, and documentation review; Claude Code for implementation, tests, and one read-only adversarial reviewer sub-agent for each of M1–M4.

### Early corrections

The first design pass had four errors. Reason codes in the diagrams did not match the API contract. The design claimed E2E tests gated deployment while CI ran only coverage and build. It described every reused consent request as `pending`, contradicting approved and declined states. It also evaluated eligibility before looking up an existing request, which would have rejected valid retries. All four were corrected; the resulting rules are in [`docs/DESIGN.md`](docs/DESIGN.md) and [`DECISIONS.md`](DECISIONS.md).

### M1 review corrections

Initial M1 implementation: [`4c504ec`](https://github.com/licaomeng/consent-gate/commit/4c504ec). Review hardening: [`9d137a1`](https://github.com/licaomeng/consent-gate/commit/9d137a1). The core held; review hardened the policy boundary and date limits.

1. **[User review] Jurisdiction normalization depended on the caller.** `evaluateDecision` / `resolveRule` matched the raw string, so a caller that skipped `parseScenario` could pass `gb`; it fell through to the `*` consent rule while the `GB` hard block sat unused. Fix: `resolveRule` now normalizes and validates at its own boundary. Tests: raw `gb` + an approved consent → `blocked / under_minimum_age`; `g!` → `validation_error`. [policy.ts:111](https://github.com/licaomeng/consent-gate/commit/9d137a1#diff-f45a01e62346f69295b931d1be8965d9fde424847d0c61f83943d7073bd6c865R111)
2. **[User review] The shared policy was mutable and `matchedRule` leaked the internal rule object.** `readonly` is compile-time only; once the policy becomes a module singleton, a downstream mutation of a result could change later decisions. Fix: freeze the policy, the rule array, and every rule, and return a copy of `matchedRule`. Tests: mutating a frozen rule throws; mutating a result leaves the policy unchanged. [policy.ts:86](https://github.com/licaomeng/consent-gate/commit/9d137a1#diff-f45a01e62346f69295b931d1be8965d9fde424847d0c61f83943d7073bd6c865R86)
3. **[User review] Implausible birth dates satisfied every age threshold.** `0000-01-01` and `1800-01-01` were accepted. Fix: reject calendar dates before 1900 and record that choice in [`DECISIONS.md`](DECISIONS.md). Tests: `0000-01-01`, `1800-01-01`, and `1899-12-31` are rejected both directly and through `parseScenario`. [age.ts:13](https://github.com/licaomeng/consent-gate/commit/9d137a1#diff-3112a58fa967dc5fe577f6dc8990f0faacfe30875c81deb5bfa41d45fe7316feR13)
4. **[User review] [`AI-USE.md`](AI-USE.md) said the implementation tool would be recorded later.** Fix: name Claude Code as the implementation tool, add this review log, and state the verification results.

Rejected suggestion: moving future-DOB validation into `parseScenario`. It needs the evaluation date, and `calculateAge` already enforces the rule on every path.

### M2 review corrections

Initial M2 implementation: [`16f130d`](https://github.com/licaomeng/consent-gate/commit/16f130d). Review fixes: [`ccbc854`](https://github.com/licaomeng/consent-gate/commit/ccbc854). The service boundary held; review closed configuration, logging, and singleton gaps.

1. **[Agent reviewer] Configuration failures were lazy and reported as client errors.** The container loaded the policy and read the evaluation date on the first request, so an invalid [`policy.json`](src/data/policy.json) or `CONSENT_GATE_EVALUATION_DATE` produced `400 validation_error`, a client-blaming answer for a server misconfiguration. Fix: the container is created eagerly at module load (build/startup) and validates the clock at construction. Test: `createContainer()` throws when the evaluation date is invalid. [container.ts:46](https://github.com/licaomeng/consent-gate/commit/ccbc854#diff-d3427ab2af2877364c0325d8924056f0e244cb6e75ca2cd27787bd0551edea74R46)
2. **[Agent reviewer] `created` was inferred from the pre-write lookup.** A conforming production repository can deduplicate inside `create` (unique constraint), so answering `201 created:true` from the earlier lookup could lie. Fix: `create` returns `{ request, created }`; the service reports `created` from the write result. Test: a repository whose lookup misses but whose write deduplicates returns `created:false`. [consent-repository.ts:19](https://github.com/licaomeng/consent-gate/commit/ccbc854#diff-440f7ea3320a788a7b31ffefb5608fafcf6a6e95a5d920ae03feb24546dd69daR19)
3. **[Agent reviewer + mutation check] Test gaps closed.** Route-level `503` for all four operations, read-only `POST /decisions` proven over HTTP, subject isolation over HTTP, `409` for adults and coverage gaps, error-message presence, and the policy-drift case where an existing record must be returned before re-evaluating eligibility under a new hard-block policy.
4. **[User review] A blank test-clock override crashed startup, and production could freeze every age.** `?.trim()` returned `""`, which `??` treated as set, so `CONSENT_GATE_EVALUATION_DATE=""` reached `parseCalendarDate` and failed during eager container creation. Separately, an accidental production value would freeze the evaluation date. Fix: blank means unset, and the override is honored only with the explicit `CONSENT_GATE_ALLOW_TEST_CLOCK=1` opt-in. Tests cover blank, absent flag, present flag, invalid value, and the in-process pin taking precedence. [clock.ts:4](https://github.com/licaomeng/consent-gate/commit/ccbc854#diff-22f824c962441fab4488e6d2e9d78f8c2e3dadda4116bfbabfd93e9db04c6cb4R4)
5. **[User review] 503 and 500 responses were unlogged.** The routes caught every error, so operators saw no stack trace. Fix: `console.error` before returning 503 or 500; expected 4xx errors are not logged and response bodies are unchanged. Tests assert one log for each server error and none for domain errors. [responses.ts:29](https://github.com/licaomeng/consent-gate/commit/ccbc854#diff-e8e89906af8e89420bd260dc446a2b1daeef3c6cdbad81320eaead9870444453R29)
6. **[User review] The container was a module-local singleton.** A Next.js module reload could reset the in-memory consent store mid-demo. Fix: store the container on `globalThis`, the standard shared-singleton pattern. Test: repeated reads return the same instance and replacement/reset still work. [container.ts:39](https://github.com/licaomeng/consent-gate/commit/ccbc854#diff-d3427ab2af2877364c0325d8924056f0e244cb6e75ca2cd27787bd0551edea74R39)

Rejected: a row vanishing between `getById` and `updateStatus` should return 404 instead of 503. The in-memory repository never deletes, there is no `await` between the check and the write, and cross-process concurrency is outside the exercise's guarantees. The pre-write check owns the 404; a write failure is a storage inconsistency (503).
